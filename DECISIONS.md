# DECISIONS.md — OrgDesign Playbook

One line of reasoning per decision, newest first.

| Date | Decision | Why |
|---|---|---|
| 2026-08-27 | **Prerender moved off the headless browser onto `react-dom/server`** (`src/entry-server.tsx` + a `--ssr` vite build) | The browser-based prerender broke the Vercel deploy: clean build hosts have no Chromium, so the step failed exactly as designed (`Executable doesn't exist at /vercel/.cache/ms-playwright/...`) and took production with it. Considered and rejected: installing Chromium during deploy (~130 MB per build plus shared-library requirements on a host with no root), and skipping the prerender on CI (ships an empty `#root` and silently undoes Phase 3). Server-rendering the same tree in plain Node needs no browser, no download and no network. It is also strictly safer — Node has no `localStorage`, so visitor state cannot be captured even by accident, which the browser version had to actively check for. Verified equivalent: crawler-visible text identical to the byte (11,633 chars), metadata surface identical (title, lang, 22 meta tags, 4 links, 6-node JSON-LD), screenshots byte-identical at 1440 px and 390 px |
| 2026-08-27 | `createRoot` retained even though hydration is now viable | The original blocker is gone — with React generating the markup there is nothing to mis-normalise — but `createRoot` is what is in production, cannot produce a hydration mismatch under any circumstance, and the only prize for switching is a marginally cheaper first paint. Prerendering here serves crawlers, not human paint time, so the added risk has nothing to pay for it |
| 2026-08-27 | Phase 3: build-time prerender via a headless browser (`scripts/prerender.mjs`), wired into `npm run build` — **superseded same day, see above** | The spec's router-based options both need a router; this repo has none. Playwright + Chromium were already in the verification workflow, so no new toolchain — playwright is now a real devDependency rather than an ambient assumption |
| 2026-08-27 | **`hydrateRoot` was tried and rejected; `createRoot` retained** | Hydration produced React #418 on every load. Cause is structural, not stateful: the prerender captures `outerHTML` from a real browser, and the browser normalises inline `style` shorthand into longhands (`background` → eight `background-*` properties). This design system styles almost everything inline, so React can never match the captured markup. `createRoot` replaces the prerendered DOM on mount — crawlers still get the full HTML, which is the entire point, and no hydration means no mismatch |
| 2026-08-27 | Storage reads moved out of `useState` lazy initialisers into mount effects (`App.tsx`, `FrameworkSection.tsx`) | Kept even though hydration was dropped: a read during first render would be captured by the prerender and ship one visitor's saved cohort to everyone. `prerender-safety.test.ts` enforces it |
| 2026-08-27 | Copyright year derived from `CONTENT_LAST_MODIFIED`, not `new Date()` | A live clock read during render bakes the build-time year into the HTML and disagrees with a client rendering after New Year |
| 2026-08-27 | Prerender fails the build loudly instead of skipping | A silent skip ships an empty `#root` while the build reports success — precisely the failure the step exists to prevent. It also refuses to capture if browser storage is non-empty |
| 2026-08-27 | Prerender auto-discovers an installed Chromium when Playwright's pinned revision is absent | Spec constraint 5: the operator will not debug. Without this, `npm run build` failed with a Playwright install banner on a machine that already had a usable browser |
| 2026-08-27 | Phase 2 executed **additively** rather than recreating the three files "exactly as follows" | The phase text assumes a greenfield; all three files already existed. Binding constraint 4 ("No phase may delete or rewrite existing content") outranks a phase instruction written on a false premise, so the missing `Claude-SearchBot` was added and nothing was removed |
| 2026-08-27 | Kept the four crawler entries the spec's list omits (Claude-Web, anthropic-ai, CCBot, Bingbot) | Deleting them would breach constraint 4 for zero benefit — all are already permitted by `User-agent: *`, so the spec's list and the current file are functionally identical. Spec §10 defers Bing deliberately, which the wildcard already covers |
| 2026-08-27 | `llms.txt` gained a linked section index and an adoption caveat; existing entity content left untouched | Phase 2 asks for a site index, but the file had become an entity/bio document across earlier sessions. Rewriting it would have destroyed the Recognition, Career and Q&A content — additive satisfies both the phase and constraint 4 |
| 2026-08-27 | `sitemap.xml` `<lastmod>` mirrors `CONTENT_LAST_MODIFIED` rather than a build timestamp | A build-time date would claim the content changed on every deploy, which is a false freshness signal; tying it to the content constant keeps the claim true |
| 2026-08-27 | **Constraint 2 of the AI-search-visibility spec amended by operator decision** — publicly LinkedIn-verifiable employment may appear in content, metadata and structured data | The spec was drafted without sight of the sessions that reconciled the site against the operator's LinkedIn export. Stripping it would have discarded verified, accurate entity corroboration. Internal org data and other named individuals remain forbidden. Recorded in SEO_BASELINE.md §Resolution so a fresh session cannot re-litigate it |
| 2026-08-27 | Phase 1: canonical host swapped from the `ericyim.example` placeholder to the real canonical origin (28 occurrences) | Everything built in prior sessions pointed at a placeholder. Acceptance criterion 4 requires one origin across canonical, og:url, JSON-LD, robots and sitemap |
